Project field guide / MVP

Inside AgentVault.

An agent can investigate a payment request. It should not be able to grant itself financial authority. Here is how the sandbox makes that distinction concrete.

01 / Architecture

Separate reasoning from authority.

The dashboard and the TrueForge agent use the same server-side policy and payment gate. Financial rules are evaluated against trusted evidence, rather than accepting the model's description of an invoice as truth.

1. Investigate →Email and ERP fixture evidence
2. Authorize →Risk rules, policy, budget reservation
3. Review →Human verification when required
4. SettleIdempotent simulated payment

The trusted server owns the decision.

React presents the workflow. The server stores transactions, evidence, review notes, reservations, and disclosure records in D1/SQLite. The agent accesses seven authenticated MCP tools, covering evidence retrieval, authorization, verification, and payment status.

The agent has no tool for changing policy or approving its own financial review. Payment requires a valid stored authorization. Atomic budget reservation protects against concurrent overspending; repeated settlement does not pay the same transaction twice.

The built-in demo is deterministic. A configured TrueForge session adds real model reasoning around the same simulated financial tools.

03 / Privacy

Inspect the disclosure boundary.

The privacy experience takes inspiration from usage meters: make sensitive disclosure visible alongside agent activity. The MVP covers outgoing MCP tool results and includes a browser-only scratchpad for trying redaction.

What happens to tool results?

  1. The trusted server retrieves the original financial evidence.
  2. The guard masks detected sensitive fields while retaining useful facts such as invoice IDs, account suffixes, and conflict signals.
  3. The agent receives the sanitized result.
  4. The disclosure ledger stores a sanitized preview and detected redaction counts for inspection.

Where does the local model fit?

An optional offline OpenAI privacy-filter adapter is included for local detection experiments. It requires separate model setup and is not loaded or wired into the default MCP guard. The default implementation uses rules.

This is not a monitor for every Codex session or all network traffic. It does not guarantee detection of every secret. Counts describe detected redactions at the covered boundary, not a complete measurement of all information sent to a model. Raw runtime event logs may still contain sensitive user or model text.

04 / TrueForge

A real agent.
Simulated finance.

TrueForge runs the accounts-payable investigation and streams tool events. The saved agentvault-ap agent uses the AgentVault MCP connector and an OpenAI model configured in your local TrueForge server.

  1. Start AgentVault with npm run dev.
  2. Start TrueForge with npm run trueforge:server.
  3. Open TrueForge on localhost:8790 and configure OpenAI in Settings → Models. Keep credentials out of chat and Git.
  4. Run npm run trueforge:setup to register the connector and AP agent.
  5. In AgentVault Integrations, choose Use agent workspace, then run npm run trueforge in a terminal.

The runner supports session resume and a human tool checkpoint before simulated payment. That runtime checkpoint is separate from AgentVault's financial approval: permission to call a tool does not override a blocked or unapproved transaction.

The hosted sandbox cannot reach a TrueForge server on your laptop's localhost. Use the local app for this setup. A ready configuration still needs a successful model session to verify credentials and quota.

06 / Honest scope

What this MVP proves.

The sandbox demonstrates enforceable policy gates, source-linked decisions, persistent human review, guarded tool output, and an integration path for model-driven investigation.

Does it send money or email?

No. Invoices, vendor replies, and settlement are simulated. This remains true when a real OpenAI model runs the investigation.

Is this production-ready financial infrastructure?

No. Organizational authentication and roles, real vendor verification, reconciliation, tamper-evident audit storage, production settlement adapters, and broader adversarial evaluation remain future work.

Can the model override a hard block?

The exposed tools do not let the agent change policy or approve its own financial review. The server enforces authorization again at payment. This is a concrete sandbox boundary, not a claim of universal resistance to every attack.

Are all duplicate invoices prevented?

Repeated authorization is identified within a run and scenario, and settlement is idempotent. A new run intentionally creates a new simulation. Cross-run real-world invoice deduplication is outside the MVP.

Where are the source and setup instructions?

The GitHub repository contains the implementation, quickstart, TrueForge integration guide, and privacy adapter documentation. Private local architecture notes are intentionally excluded from Git.
